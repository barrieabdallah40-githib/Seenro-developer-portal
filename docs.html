02 · GET STARTED

Quick start

  1. Create an account. Register in the developer portal; complete email verification if enabled.
  2. Create a project. Sign in and create a project in your workspace.
  3. Create a project API key. Select only the scopes your trusted server needs.
  4. Store the secret safely. The full key is shown only at creation. Save it in a server-side secret manager.
  5. Call the API. Use the API base URL and endpoint-specific authentication method.

Never put a secret project API key in browser JavaScript, a public repository, or a mobile application bundle.

03 · ACCESS CONTROL

Authentication and API keys

Developer session

The portal uses a developer login session to manage that developer's projects and API keys. These management calls use the session as a Bearer token.

Project-bound developer API keys

Keys are project-bound. Core stores a hash; the full secret is returned only at creation. They are intended for trusted server-to-server use. Core checks project association and assigned permissions.

ScopePurpose
projects:readRead permitted project information.
projects:writeCreate or modify permitted project resources.
data:readRead project data records.
data:writeCreate, update, or delete project data records.
auth:readPermitted application-authentication reads.
auth:writePermitted application-authentication writes.

These are the scopes currently exposed by the portal. Do not assume they grant storage permissions. Storage-key authentication is separate; use the matching Core contract for its credential format and schema.

05 · DEVELOPER STORAGE

Store files for your project

SEENRO Storage provides project-scoped file storage, Storage API key management, usage tracking, and subscription checkout. Developers integrate Storage into their own applications through a trusted server-side environment. Create and manage project Storage API keys in this portal, then keep each secret key in your server's environment variables or secret manager. Never expose an st_live_ key in browser JavaScript, a mobile application, a public repository, or code delivered to customers.

Your application backend uses its Storage API key for authorized server-side Storage operations. For customer uploads, the intended integration is for your trusted backend to authorize the upload. Customers should not need a SEENRO developer account or a Storage API key. SEENRO manages the storage backend, object handling, project capacity, usage, and applicable subscription enforcement.

The developer portal manages Storage keys, subscriptions, checkout, and usage. It is not intended to be a browser-based object upload, download, or deletion console.

Product limits: non-video files up to 100 MiB; MP4, MOV, and WebM videos up to 250 MB and 5 minutes. Video size and duration limits are independent. Original uploaded bytes are preserved without forced compression.

POST /projects/{project_id}/storage/subscriptions/checkoutCreate a storage-plan checkout.
GET /projects/{project_id}/storage/keysList project Storage API keys.
POST /projects/{project_id}/storage/keysCreate a project Storage API key.
DELETE /projects/{project_id}/storage/keys/{key_id}Revoke a project Storage API key.
GET /projects/{project_id}/storage/usageRead project storage usage.

Payment and capacity safety

  • Checkout starts a payment flow; it does not itself grant capacity.
  • Capacity is granted only after Core independently verifies settlement.
  • A browser redirect or client-supplied payment status is not proof of payment.
  • Storage API keys are separate from developer API keys. Keep Storage secrets server-side.

The portal's key management, subscription, and usage features do not by themselves verify the complete customer-upload integration. Verify server-side authorization, upload restrictions, object access, payment settlement, and renewal end to end before relying on the complete flow in production.
